# SLIM Next M2 dependency plan — 2026-09-08

Status: M2 preparation; the native block component is verified, while source
cutovers have not started.
Planning base: `bead09c` on `codex/slim-next`.

[RFC-0112](../../design/rfcs/0112-agent-development-and-os-foundation.md)
defines M2; [RFC-0123](../../design/rfcs/0123-milestone-evidence-and-experiment-boundaries.md)
keeps successor decisions separate from completed milestones. M0 and M1 remain
complete. The [M1 closure](2026-09-08-m1-closure.md) identifies the full passing
compiler gate at `4bdb675` and later reporting validation separately. This plan
records dependencies; accepted child decisions below do not establish milestone
completion or measured language benefits.

## Decision prerequisites

The labels below identify child RFC topics. P was explicitly approved and
implemented as [RFC-0147](../../design/rfcs/0147-scoped-m2-feature-experiments.md); C is drafted
as [RFC-0148](../../design/rfcs/0148-staged-successor-compatibility.md). O, L and R
are drafted as [RFC-0149](../../design/rfcs/0149-uniform-moves-and-lexical-references.md),
[RFC-0150](../../design/rfcs/0150-checked-slices-and-owned-bytes.md) and
[RFC-0151](../../design/rfcs/0151-memory-domain-and-cleanup-abi.md). C/O/L/R remain
proposed. R now has proposed [provider](../../design/rfcs/0152-bounded-hosted-pool-provider.md)
and [allocation-API](../../design/rfcs/0153-explicit-allocation-authority-and-reservation.md)
children, with the separately accepted [native block component](../../design/rfcs/0154-native-pool-component.md)
providing bounded C evidence. Worker-domain and hosted-adapter contracts still
precede provider/source acceptance. Assign other numbers when drafting. Each needs concrete canonical
syntax where applicable, checked semantics, bounds and exhaustion behavior,
diagnostics, migration, tests, costs, and explicit supersession of older decisions.
Use RFC-0112's delegated decision scope without treating it as a hard-gate waiver.

| Label / proposed child RFC | Decision required before dependent implementation |
| --- | --- |
| P — M2 experiment policy (process) | Resolve the sugar/elaboration prohibition and primitive-rating conflicts in AGENTS.md and FEATURE_POLICY explicitly. | U — Storable Unit (language) | Replace Void and its value spelling, including storage/layout, statements, signatures and C ABI consequences. Retain one unit type. |

P must resolve applicable policy conflicts before acceptance of conflicting
language children. C and the complete O/L/R contract package must be accepted
before changing ownership syntax or byte representation: allocator lifetimes,
borrow validity and destruction cannot be designed independently. Other children
need acceptance before their own slice. A library-only implementation needs no
new primitive; any unavoidable container primitive needs its own accepted RFC.

## Dependency-ordered slices

Each row is a reviewable exit boundary, not a requirement to combine its changes
in one commit. C must specify any coupled atomic cutover before work begins;
never publish an intermediate state that frees storage behind a live old Bytes
view. Every implementation checkpoint remains executable through selfhost/ and
the portable seed. Carry migrated compiler/library/fixture coverage at each
source cutover, rather than leaving the bootstrap migration until closure.

| Slice | Needs | Bounded deliverable and focused exit evidence |
| --- | --- | --- |
| 00: contracts and workload freeze | P, C; then O/L/R | Accept the decision package. Inventory affected surface, host APIs, fixtures, retained queries and baseline rows. Freeze two application oracles and representative workloads before implementation measurements. |
| 01: Unit | 00, U | Migrate Void atomically; exercise stored/returned Unit, aggregates, layout and invalid discard diagnostics. |
| 02: uniform moves and reference parameters | 01, O | Replace owning markers across bindings, calls, aggregates, assignments, insertion and returns; preserve fresh temporaries and evaluation order. Cover branches, reinitialization and overlapping argument loans. |
| 03: lexical reference values and slices | 02, L | Check local/returned lifetime relationships, shared/exclusive reborrows and collection invalidation. Reject escaping, conflicting and out-of-bounds cases; cross mandatory work limits. |
| 04: private representation | 03, V | Migrate one concrete library type; verify cross-module construction/access rejection, public API use and domain distinction. |
| 05: allocator-domain foundation | 03, R | Establish checked domain relationships and runtime protocol using concrete types; test domain escape, teardown and hosted authority plumbing. Keep fallible public allocation cutover in 08. |
| 06: owned Bytes cutover | 05, L, C | Replace copyable views with owners or checked slices throughout compiler/library/host boundaries. Verify freeze without copying, static literals, returned slices and old-view escape regressions. |

| 10b: loops and exits | 10a, F | Extend the sole checker's control/ownership and cleanup edges; test zero/multiple iterations, nested exits, joins and bounded fixed-point exhaustion. Preserve required tail-recursion stack behavior. |

If 12 requires interface-dependent operations, defer those operations to 13;
do not accept a generic body only because one convenient instantiation works.
RFC-0109 remains contrary evidence: compiler C grew 13.6% for only 85 source
bytes removed. Passing conformance alone does not establish abstraction value.

## Workloads, bounds and scope

Proposed substantial applications are a bounded in-memory key/value request
processor with an independent state model, and a framed message codec/parser
with a separate round-trip/error oracle. Both must exercise shared library
ownership, results and container/callable APIs across distinct value types;
tiny renamed examples do not meet the exit criterion. A queue/allocation workload
adds pressure on reuse, cleanup and exhaustion. Freeze concrete input limits,
fault counts and independent acceptance tests in 00. Durable storage, crash
replay and simulated providers remain M4/M7 work.

At 00 audit whether these workloads require additional fixed-width integers,
USize, arrays, bit operations or target layout contracts. If required, add a
separate child RFC and slice before its first consumer; RFC-0112's type sketch
does not itself authorize implementation. Do not quietly fold the complete M5/M6
systems surface into M2. Source total/no_trap/stack/work contract syntax likewise
needs a dedicated child decision if needed; E alone must preserve independent
evidence without claiming those contracts implemented. Debugger/context APIs,
resource handles, arbitrary destructors, atomics, cancellation and a new backend
are outside this plan.

## Verification and compact evidence

Every semantic slice adds positive, negative and stable diagnostic tests through
the production compiler. Use a named bounded cross-product of owning destination,
place shape, borrow mode, branch/loop exit and failure point; report its actual
dimensions, limits and coverage instead of claiming universal safety. Mandatory
checking exhaustion rejects; optional analysis remains bounded/unknown.

Extend M1 clean/retained comparisons for each new consumed input: reference and
allocator lifetimes, copy/layout/private-API changes, cleanup/effects, generic
requirements, instance keys and configured budgets. Compare complete diagnostics
with current spans, full analysis records, deterministic C and native behavior
through edits, rejection/recovery, corruption and reset. Preserve transactional
publication and explicit last-good artifacts.

Before committing compiler/runtime/benchmark/agent-tool changes, retain all
AGENTS.md commands unchanged:

```sh
./bootstrap.sh
cargo run --bin slim-govern -- check
cargo test
cargo run --release --bin slim-bench -- performance --quick
cargo run --release --bin slim-bench -- reduction --quick
cargo run --release --bin slim-bench -- parallelism
cargo run --release --bin slim-bench -- compare --quick
cargo run --release --bin slim-bench -- agent
```

At M2 closure run the complete `scripts/verify-0.9.sh` release gate, including
repository campaigns, reproducible packages, clean installation, ABI rejection
and website checks. C must explicitly map any renamed release entry point while
preserving all obligations. Keep sanitizer/fault campaigns, deterministic work
and geometric scaling, native analysis/resource baselines and both state_machine
and signal_network parallel/forced-serial ratios. Explain every changed baseline
row, including non-primary hazards. No limit or timeout relaxation is proposed;
an actual conflict blocks its slice under the existing +60 exception policy.

Measure same-host before/after frontend and backend work/time, setup/reset,
runtime, allocations/frees, peak memory, source/generated/binary size and
specialization counts separately. Calibrate additional memory/code-size budgets
from frozen workloads before adopting dependent capabilities; do not invent
passing thresholds after seeing a candidate. Keep M1's slower body-update and
setup-recovery costs visible. Agent productivity remains unknown without the
separate controlled evaluation; source/edit savings are only proxies.

Keep one small current ledger: slice, accepted RFCs, source/seed/config identity,
command result, evidence method/domain/budget, measured delta, blockers and raw
archive link. Use the [evidence storage policy](README.md#recording-future-checkpoints):
routine reruns stay ignored; preserve decision timings, failures, contrary results
and closure receipts in immutable compressed archives. Do not copy M1 logs or
relabel historical passes. This planning edit requires documentation/governance
validation only; it cannot count as an M2 implementation or release pass.
