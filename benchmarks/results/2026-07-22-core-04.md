# Core 0.4 freeze evidence

Date: 2026-07-22  
Platform: macOS arm64  
Scope: lifetime planning, regions, deterministic destruction, and typed
allocation failure; no unrelated performance optimization

## Implemented boundary

- `selfhost/memory.slim` is the canonical SLIM implementation of recursive
  storage classification and typed `ValuePlan`, `AllocationPlan`,
  `DestructionPlan`, `FunctionPlan`, and `Plan` records.
- Detailed name liveness and escape analysis examines at most 64 values per
  function. Larger functions conservatively use the function endpoint and
  summary escape; the fallback cannot shorten a lifetime.
- The self-hosted backend selects a nested child region for functions with no
  storage-bearing result and no `inout` output. Other allocations use the
  caller's destination region. Region descriptors and ordinary values are
  stack placed; dynamic vector and arena buffers remain region allocated.
- Allocation headers identify their region directly. Reallocation no longer
  searches a process-global list, and destruction releases newest allocations
  first.
- RFC-0026 replaces allocation traps with one `SlimAllocStatus` carried by the
  declared `alloc` effect. Generated branches propagate failure, clean active
  regions, and handle it once at process entry with exit code 71.
- Memory plans use the existing declaration body/interface invalidation split;
  no second persistent cache or source annotation was added.

## Combined gate

`./scripts/verify.sh` passed formatting, warning-free Clippy, all Rust and
end-to-end tests, governance, differential conformance with zero deferrals,
the self-host fixed point, clean/incremental/project scaling assertions, and
ASan/UBSan native execution. The sanitizer test injects failure at allocation
ordinals 1 through 6 and requires exact exit status and diagnostics at every
point.

The frozen self-host fixed point is 829,446 identical stage-2/stage-3 C bytes.
The production Rust code generator is 31,584 bytes against its unchanged
32,112-byte ceiling; no dependency or source-language primitive was added.

The quick clean-scaling series remained approximately linear:

| declarations | source bytes | check us | emit us | check ns/byte |
| ---: | ---: | ---: | ---: | ---: |
| 250 | 17,612 | 463 | 658 | 26.32 |
| 500 | 35,362 | 892 | 1,347 | 25.24 |
| 1,000 | 70,862 | 1,964 | 2,682 | 27.73 |
| 2,000 | 143,862 | 3,833 | 5,106 | 26.65 |

These are gate measurements, not a performance-optimization claim. Core 0.4
deliberately leaves per-binding early destruction, dynamic-buffer stack
promotion, conditional removal of the internal region ABI from pure calls, and
allocator tuning for later measured work.
